# 路线一：基于 iCal / Webcal (.ics) 的日程同步方案

## 1. 方案背景与目标
- **痛点**：当前小屏幕设备（480×480）缺乏便捷的文本输入途径，直接在设备上手动增删改日程体验极差，且会导致数据孤岛。
- **目标**：用户在手机或 PC 上的常用日程软件中维护日程，设备端以只读订阅方式自动同步并渲染到时间轴上，实现“**手机输入管理，小屏扫视查看**”。

---

## 2. 方案优势与生态兼容
- **全平台标准通用**：基于国际标准的 iCalendar 规范（RFC 5545）。
- **零登录成本**：设备无需内置浏览器或运行复杂的 OAuth / Webview 登录流程，只需一条订阅链接（URL）即可拉取数据。
- **免开发者审核**：无需向各开放平台申请应用资质和 API 审核。
- **支持的主流服务**：
  - **Apple 日历**（iPhone / Mac 系统自带日历）：直接分享并复制公共/共享日历链接；
  - **Google Calendar / Outlook**：设置中自带公开或私密的 iCal 格式订阅地址；
  - **飞书 / 钉钉日程**：支持导出个人/团队日历订阅 URL；
  - **滴答清单 (TickTick)**：支持生成日历订阅链接。

## 3. 技术实现步骤规划 (TODO Checklist)

### 阶段一：日程数据模型与时间轴 UI 渲染
- [ ] **定义数据结构**：在项目中增加 `src/calendar.rs` 或 `src/event.rs`：
  ```rust
  pub struct CalendarEvent {
      pub id: String,
      pub title: String,
      pub start_time: DateTime<Local>,
      pub end_time: DateTime<Local>,
      pub is_all_day: bool,
  }
  ```
- [ ] **时间轴 Canvas 渲染**：
  - 在 [`src/timeline.rs`](../src/timeline.rs) 中计算事件起止时间对应的 Y 轴区间：
    - `start_y = PAD_Y + (start.hour() * 60 + start.minute()) as f32;`
    - `end_y = PAD_Y + (end.hour() * 60 + end.minute()) as f32;`
  - 在轴线右侧绘制圆角半透明事件色块、事件名称与起止时间；
  - 支持多事件垂直顺序与视觉层次（纯黑背景下的高对比度配色）。
- [ ] **本地 Mock 测试**：先硬编码或从本地测试数据载入 2~3 个日程，跑通界面展示。

### 阶段二：iCal (.ics) 解析引擎
- [ ] **引入解析依赖**：在 `Cargo.toml` 中引入轻量 iCalendar 解析库（如 `icalendar` crate）。
- [ ] **事件过滤与时区处理**：
  - 仅提取当天（或前后数天）处于激活状态的事件；
  - 妥善处理时区偏移（UTC 与 Local 时间转换）；
  - 处理全天事件与跨天事件的展示逻辑。

### 阶段三：网络拉取与定时后台同步
- [ ] **网络请求客户端**：引入轻量 HTTP 请求库（如 `reqwest` 或更轻量的 `ureq`）。
- [ ] **后台轮询任务**：
  - 接入 `iced::Subscription`，每 10~15 分钟在后台异步 GET 一次订阅链接；
  - 拉取成功后自动触发界面状态刷新，时间轴动态更新最新日程。
- [ ] **离线缓存机制**：
  - 将拉取到的最新 `.ics` 内容或解析后的数据缓存到本地（如 `cache/calendar.ics`）；
  - 网络断开或开机无网时，自动读取本地缓存保证基本显示。

### 阶段四：设备端免打字配置方案
- [ ] **基础版（配置文件）**：在本地 `config.toml` 中配置 `calendar_url`。
- [ ] **设备友好版（局域网配对 Web 页面）**：
  - 设备启动后若未配置日历，在屏幕上显示局域网 IP / 端口提示或二维码（如 `http://192.168.1.xxx:8080`）；
  - 用户用手机连接同局域网，浏览器打开网页直接粘贴日历订阅链接，点击保存；
  - 设备端热重载配置并开始拉取。
